
| 字段                         | 解释                 |
| -------------------------- | ------------------ |
| `rule_id`                  | **规则名称**           |
| `source_case / problem_id` | **case来源/编号**      |
| `category / object_type`   | **问题类别/对象**        |
| `problem_pattern`          | **错误是什么**          |
| `observable`               | **错误证据**           |
| `root_cause`               | **错误原因**           |
| `recognition`              | **Agent 应该怎么判断**   |
| `evidence / 案例绑定`          | **这条规则的依据在哪里**     |
| `standard_fix`             | **官方示例展示的标准修法**    |
| `equivalent_fix`           | **其他被材料明确允许的等价修法** |
| `forbidden_fix`            | **禁止采用的修复方法**      |
| `verification`             | **如何证明修改正确**       |
# 用一个例子理解整张卡

假设任务要求：

```
rx_fifo_partition:
    u9
    u10
    u11

tx_fifo_partition:
    u3
    u4
```

但 Agent 生成的 Dofile 写成：

```
rx_fifo_partition
├── u9
└── u10

tx_fifo_partition
├── u3
├── u4
└── u11
```

那这张规则卡就可以这样填：

```
rule_id:
DFT-PARTITION-FUNCTION-OWNERSHIP “功能分区归属”。

problem_pattern:实例被分错或遗漏

observable:partition report 显示 u11 在 tx_fifo_partition

root_cause:Dofile 中 partition include 范围写错

recognition:task_spec 要求 u11 属于 rx_fifo + 网表确认 u11 存在 + report 显示 u11 实际属于 tx_fifo

standard_fix:把 u11 从 tx_fifo 移回 rx_fifo

verification:重新运行后，rpt_scan_partition 显示 u11 ∈ rx_fifo_partition且没有 scan chain 跨 partition
```
