## 2.6 扫描设计规则

Scan 模式下，所有会干扰“触发器按我的要求移位和捕获”的东西，都必须变得可控、确定、可预测。

### 2.6.1 Tristate Buses —— 三态总线

任何时刻最好只有一个 Driver 真正在驱动 Bus。

> 功能模式及 Capture 时 ATPG 可以安排测试向量保证只有一个 Driver 控制总线，但 **Shift 时 Scan FF 不停变化，因此不能保证这一点**。

如果 `EN1 EN2 EN3` 恰好又受 Scan FF 控制，那么 Shift 时：

```
Scan FF 状态一直在变
↓
EN1/EN2/EN3 一直变
↓
不知道哪几个 Driver 被打开
```

于是可能出现：

```
D1 = 1，同时驱动 BUS
D2 = 0，同时驱动 BUS
```

> **Bus Contention，总线争用。**

解决办法：当：SE = 1也就是 Shift 模式时，直接强制：

```
EN1 = 1
EN2 = 0
EN3 = 0
```

不管 Scan FF 里移的是什么东西：**总线控制权固定下来。**

> ## Floating Bus

```
EN1 = 0
EN2 = 0
EN3 = 0
```

所有 Driver 都关了：BUS = Z，Bus 没有人驱动，值可能不可预测。

因此建议使用：

*   pull-up
*   pull-down
*   bus keeper

其中 bus keeper 为保持。

### 2.6.2 Bidirectional I/O —— 双向端口

**当&#x20;**`SE=1`**&#x20;时，强制输出三态 Buffer 关闭，让 Tester 驱动该 I/O。** Capture 时再由测试向量确定端口到底作为输入还是输出。

可以直接记：

> **双向 I/O 在 Shift 阶段必须定方向。**

### 2.6.3 Gated Clock —— 非常重要

门控时钟的目的通常是：**省功耗。**

比如：

```
       EN
       │
CK ─── AND ─── GCLK ─── DFF
```

如果：

```
EN = 0
```

则：

```
GCLK 不跳
```

DFF 不翻转，自然省动态功耗。实际设计通常会有 latch/ICG，但思想一样。但是到Scan Shift 模式这变成了灾难，Scan Chain 本质是：

```
SFF1 → SFF2 → SFF3 → SFF4
          ↑
       每个 FF
       都得吃到 Clock
```

可是：

```
SFF1：CK 正常
SFF2：CK 正常
SFF3：GCLK 被关
SFF4：CK 正常
```

发一个 Shift Clock：

```
SFF1 动
SFF2 动
SFF3 不动！
SFF4 动
```

整条链立刻乱套。

因此：

> **Shift 时 Scan Clock 必须能够到达所有需要 Shift 的 Scan FF。**

clock gating 会造成某些 FF 的 clock port 无法直接由 primary input 控制，因此必须修改结构以支持 Shift。

测试时强制：

```
Clock Enable = 1
```

例如教材 Figure 2.23：

TM = Test Mode 整个测试期间都为测试模式

SE = Scan Enable SE = 1 → Shift SE = 0 → Capture

![\<img alt="" width="495" height="205" data-attachment-key="B32XLEZE" data-annotation="%7B%22attachmentURI%22%3A%22http%3A%2F%2Fzotero.org%2Fusers%2F19118036%2Fitems%2F363B27Q5%22%2C%22annotationKey%22%3A%22G4P7W849%22%2C%22color%22%3A%22%23ffd400%22%2C%22pageLabel%22%3A%2273%22%2C%22position%22%3A%7B%22pageIndex%22%3A103%2C%22rects%22%3A%5B%5B135.561%2C249.313%2C432.833%2C372.442%5D%5D%7D%7D" src="attachments/B32XLEZE.png" ztype="zimage"> | 495](attachments/B32XLEZE.png)

CEN = 1，不管功能逻辑想不想关 Clock，**Clock 都必须打开。**

但如果使用 TM 强制 Clock Gate 打开，原本 Clock Gating Logic 自己就测不到了。因为你整个测试期间把它绕开了。这会导致 clock gating logic 中的 fault 无法检测，从而造成 fault coverage loss。

如果SE = 1 强制 Clock Gate 打开那么：Scan chain 正常移动。Capture

```
SE=0
→ 不再强制
→ Clock Gate 回归功能逻辑控制
```

这样 ATPG 就有机会：**测试 Clock Gating Logic 自己。**

因此教材说：

*   用 `TM`：简单，但是 fault coverage 较低；
*   用 `SE`：coverage 更高，但 ATPG 更复杂。

这是非常典型的 DFT trade-off。

### 2.6.5 Combinational Feedback Loop

推荐：**从 RTL 根源消除不合理的组合反馈。**

教材也是这么说的。如果 RTL 改不了，可以使用：

```
TM
```

在 Test Mode：强制断开 feedback

把：

```
A → logic → B
↑           │
└───────────┘
```

改成测试时：

```
A → logic → B
```

`feedback：X`

教材将这种处理描述为插入 scan point，控制/观测并打断这个 loop，而且这里是 Shift、Capture 整个测试期间都要避免该反馈环。

### 2.6.6 Asynchronous Set / Reset

如果 Scan Cell 的异步 set/reset 不能直接从 Primary Input 控制，它们可能阻止 Scan Chain 正常 Shift，因此 Shift 时必须将其强制到 inactive state。

```
TM=1
↓
强制 RL=1
```

于是整个测试期间：Reset 永远不会突然触发

Shift 很稳定。却把 Reset Logic 藏起来了。

### 2.7.2 扫描合成

#### 2.7.2.1 扫描配置

扫描配置描述了扫描链规划的初始步骤，在这里确定扫描设计的总体结构。此阶段主要决策包括：（1）扫描链数量;（2）用于实现这些扫描链的扫描单元类型;（3）存储元件应排除在扫描合成过程中;以及（4）扫描单元在扫描链中的排列方式。

图2.29a展示了由**负边扫描单元和正边扫描**单元组成的电路结构示例。相关的定时图（见图2.29b）展示了电路结构的正确移位时序。在每个移位时钟周期中，Y首先在上升的CK边取态X，然后X在下降的CK边加载SI值。如果我们不小心把正边扫描单元放在负边扫描单元之前，两个扫描单元在每个移位时钟周期结束时总是错误地包含相同的值。

在扫描链必须包含多个不同时钟域的扫描单元时，会在相邻的跨时钟域扫描单元之间插入**锁存**锁存，以确保时钟间任何时钟偏斜都能被容忍。不同时钟域之间的时钟偏斜是预期的，因为时钟域内控制时钟偏斜以保持在某个阈值以下，但不同时钟域之间则无法控制。因此，如果未插入锁定锁存，这两个扫描单元之间可能会因保持时间违规而发生竞速。

通过锁定锁扣进入CK2领域。相关的时序图见图2.30b，其中CK2在CK1之后到达，以展示时钟偏移对跨时钟域扫描单元的影响。在每个移位时钟周期中，**X首先在上升的CK1边缘取SI值**，然后**Z在上升的CK2边取Y值**。最后，**新的X值被转移到CK1下降边的Y**，以存储SCp内容。如果CK2比CK1早到，Z将首先在上升的CK2边取Y值。然后，X 会在上升的 CK1 边取 SI 值。最后，新的X值被转移到CK1下降边的Y，以存储SCp内容。在这两种情况下，图2.30a中的锁止**锁存设计允许无论CK2比CK1早还是晚到，都能正确操作换挡**。需要注意的是，该方案仅在CK1和CK2之间的时钟偏斜小于时钟脉冲的宽度（占空比）时有效。如果不是这样，那么减缓移位频率或扩大移位时钟的占空比可以保证这种方法能适用于任何时钟偏移的情况。也可以使用其他锁闭锁扣和锁止触发器设计。

#### 2.7.2.2 扫描替换

扫描配置完成后，扫描替换会用功能等效的扫描单元替换可测试设计中所有原始存储元件。在使用单次或单次合成的情况下，扫描替换对工具用户来说是透明的。最近，一些RTL扫描合成工具甚至在进入逻辑/扫描合成工具之前，就已经实现了RTL的扫描替换，以反映原始RTL设计中的扫描设计变化。

#### 2.7.2.3 扫描重排

扫描重排是指根据物理扫描单元位置，将扫描单元按扫描链重新排列的过程，以尽量减少用于实现扫描链的互连量。

扫描链间重序，即扫描单元在不同扫描链间重新排序，必须确保扫描链的时钟结构得以保持。无论是扫描链内重序还是扫描链间重序，都必须注意限制扫描单元之间的最小距离，以避免时序违规

#### 2.7.2.4 扫描缝合

扫描缝合是指将每个扫描单元的输出连接到下一个扫描单元的扫描输入.

如果使用共享I/O端口连接到扫描链输入或扫描链输出，则必须额外连接信号到共享I/O端口，以确保其在整个移位操作中始终分别表现为输入或输出。

在扫描缝合步骤中，常会插入锁定锁扣或锁定触发器，以连接可能出现时钟偏移的相邻扫描单元。这些锁定锁扣或锁止触发器随后被缝合在相邻的扫描单元之间。

### 2.7.4 扫描验证

当扫描设计的物理实现完成，包括所有单元的布置和布线后，会生成一个标准延迟格式（SDF）的定时文件。

除了时钟偏移问题外，还可能出现其他扫描移位问题。通常，它们源于

（1）扫描初始化序列错误，未能将设计置入测试模式;

（2）扫描设计规则检查和修复不完整，某些扫描单元的异步设置/复位信号在换位操作期间未被禁用，或某些扫描单元的门控/生成时钟未正确启用或禁用;或者

（3）错误的扫描合成，即正边扫描单元置于负边扫描单元之前。扫描捕获问题通常由于测试生成和故障仿真工具中使用的零延迟模型与真实设备的全时序行为不匹配而发生。

在这些情况下，扫描设计和测试应用过程中必须注意：（1） 在所提供时钟之间提供足够的时钟延迟，使时钟捕获顺序具有确定性，（2） 防止同时发生时钟和数据切换事件。未能正确考虑时钟事件，很容易导致用于测试生成和故障仿真过程中的零延迟（基于周期）模拟器出现故障。关于转移和捕获操作扫描验证的更详细信息，详见下文。
