## 三、三周学习方案

### 第 1 周：门级 Verilog、Liberty、Scan 基础

|单元|内容|实验产物|通过标准|
|---|---|---|---|
|1|HDLBits：Verilog Language、Combinational Logic、Sequential Logic|组合门、DFF、移位寄存器、FSM|能独立写出可综合的 `always @(posedge clk)` 和结构化门实例|
|2|Yosys 官方 `cell_libs` counter 示例|`counter.nl.v`、`mycells.lib`、综合日志|能解释 `techmap`、`dfflibmap`、`abc -liberty` 各自作用|
|3|门级网表分析|`design_summary.json`|对每个实例回答：cell type、端口连接、时钟、复位、驱动来源|
|4|Yosys JSON + Pyverilog + Liberty parser|网表与 Liberty 的 cell/pin 对照表|能判断网表中的 cell 是否在 Liberty 中存在，且引脚方向一致|
|5|自建 4-bit Scan Chain|`scan_ff.v`、`scan_chain4.v`、自检 Testbench、VCD|能完成 Shift-In → Capture → Shift-Out，并用 GTKWave 解释波形|
|6|Full Scan、Partial Scan、双链平衡|1 链和 2 链的周期比较表|能计算最大链长、移位周期，并说明链平衡对测试时间的影响|

Scan Cell 的最小接口可以固定为：

```
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 1'b0;
    else
        q <= scan_enable ? scan_in : d;
end
```

### 第 2 周：多时钟、混合边沿、Lockup

|单元|内容|实验产物|通过标准|
|---|---|---|---|
|7|同时钟、同边沿 Scan|基线波形|能解释为什么普通链不需要 Lockup|
|8|同边沿、跨时钟域 Scan|加入可控时钟 skew 的 Testbench|能指出 hold 风险来自哪个时钟到达关系|
|9|正沿/负沿混合 Scan|`posedge→negedge`、`negedge→posedge` 两组波形|不死记排序规则，能依据 launch/capture 边沿和半周期裕量判断|
|10|Lockup Latch 与 Lockup FF|无 Lockup/有 Lockup 的对照波形|能说明 Lockup 的透明窗口、额外延迟和面积代价|
|11|Gated Clock、Derived Clock|test-enable 和 capture 时序实验|能区分“时钟没有脉冲”和“时钟脉冲不可控”|
|12|OpenSTA 最小时序分析|Liberty + Verilog + SDC + `report_checks -path_delay min`|能把仿真中的 skew 现象与实际 min-delay 报告对应起来|

建议保留下面这张四类实验矩阵：

|情形|主要风险|处理|验证|
|---|---|---|---|
|同时钟、同边沿|常规 setup/hold|普通串接|Scan 仿真|
|同边沿、不同 clock|Hold violation|Lockup Latch/FF|skew 仿真 + OpenSTA|
|混合正负边沿|边沿顺序和占空比风险|比较两种排序|波形 + min-delay|
|门控/派生时钟|Shift/Capture 时钟不可控|test enable、clock grouping|时钟波形 + 时序报告|

注意：零延迟 Verilog 仿真不能证明真实 hold timing。它只能帮助理解事件顺序；最终应使用 Liberty/SDC/SDF 或比赛工具报告验证。

### 第 3 周：EQY 最小案例与整合

#### 1. 先跑官方计数器案例

```
git clone https://github.com/YosysHQ/eqy.git
cd eqy/examples/simple
eqy -f counter.eqy
```

官方 `counter.eqy` 的核心结构是：

```
[gold]
read_verilog counter.sv
prep -top counter

[gate]
read_verilog counter.sv
synth -top counter

[strategy simple]
use sat
depth 10
```

然后再按 [NERV Quickstart](https://yosyshq.readthedocs.io/projects/eqy/en/latest/quickstart.html) 运行一个“故意引入 bug → EQY 找到失败分区 → 修复后 PASS”的案例。

#### 2. 自建三类 EQY 结果

|案例|修改|预期结果|应检查|
|---|---|---|---|
|PASS|Gold 与 Gate 功能相同，仅改变结构|`PASS`、退出码 0|`logfile.txt`、策略状态|
|FAIL|修改一个条件、位宽或常量|`FAIL`，通常会指出失败 partition|失败分区、VCD trace|
|CONFIG_ERROR|错误 top、缺少 cell model、文件路径错误|配置/解析错误|`gold.log`、`gate.log`、`combine.log`，不要误判成逻辑不等价|

EQY 官方输出目录文档规定了：

- 整体成功会生成 `PASS`
- 整体失败会生成 `FAIL`
- 每个策略目录下还会有 `status`，状态可能是 `PASS`、`UNKNOWN`、`FAIL` 或 `ERROR`

#### 3. 最终整合实验

推荐的边界是：

```
原始 RTL
  ↓ Yosys
原始 Pre-scan 门级网表
  ↓ 最小网表修复
修复后的 Pre-scan 门级网表
  ↓ EQY
功能等价通过
  ↓ Scan 插入
Post-scan 网表
  ↓ Icarus/GTKWave
Shift/Capture/Shift-out 验证
```

不要直接把一个增加了 `SI/SE/SO` 端口的原始 Post-scan 网表，和没有这些端口的 Pre-scan 网表做无约束 EQY。二者接口和状态空间已经变化；如果比赛脚本要求比较它们，需要按官方脚本提供的功能模式映射或约束执行。
