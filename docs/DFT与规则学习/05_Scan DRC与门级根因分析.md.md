# 05. Scan DRC 与门级根因分析

Scan DRC（Design Rule Check）不是考试式的红叉清单，而是一个问题定位入口。它告诉你某个对象在移位或捕获时可能不可控、不稳定或不可观；真正的修复必须继续追到门级结构，判断应改 Dofile、约束还是网表。

## 1. 先分清四层信息

遇到一条违规，按下面四层记录，避免“看见报错就改参数”：

1. **现象**：工具输出的原文，例如“时钟不可控”“异步复位未禁用”；
2. **违规对象**：具体端口、网、单元、引脚或链段；
3. **结构根因**：门级连接为什么导致该现象；
4. **修复动作**：改 Dofile/DFT 约束、改网表结构，或明确无法修复的边界。

只有把四层都写出来，另一名成员才能复核你的结论。赛题指南把任务二的问题也按执行、设计/结构、配置和输出等类别区分，不能用一个“DRC 通过”覆盖全部要求。[赛题指南第 4.2.2 节](<../赛题二-基于大语言模型的Scan Insertion智能体系统设计.md>)

## 2. 常见规则与门级直觉

### 2.1 时钟、复位、置位不可控

Scan Cell 需要在 Shift/Capture 期间得到可预测的时钟和控制。如果时钟来自内部状态机，或异步复位由某个未初始化寄存器产生，测试仪就无法稳定控制它。门级追踪时要从 Scan Cell 的 `CK/RN/SN` 等引脚反向查驱动锥，确认最终是否连到可控顶层端口或测试旁路。

### 2.2 门控时钟无法开启或捕获

门控逻辑可能在功能模式省电，却在 `SE=1` 时把移位时钟挡住；若整个测试期间强行打开，也可能失去对门控故障的覆盖。应先确认任务需要“仅 Shift 旁路”还是“Shift+Capture 都旁路”，再决定约束或网表动作。[英文 DFT 教材第 2.6.3 节](<../../学习材料/DFT补强/VLSI Test Principles and Architectures - Design for Testability.md>)

### 2.3 派生时钟未旁路

PLL、分频器、脉冲发生器或内部寄存器产生的时钟不能直接由测试端口控制。若测试模式没有选择外部可控时钟，相关单元可能完全不移位。重点不是“时钟名字里有没有 `clk`”，而是追踪它是否经过时钟生成逻辑。[英文 DFT 教材第 2.6.4 节](<../../学习材料/DFT补强/VLSI Test Principles and Architectures - Design for Testability.md>)

### 2.4 时钟误接到数据、复位或置位

门级网表中一个端口角色接错，可能让时钟脉冲直接改变数据输入，或让复位端收到周期性翻转。此类问题通常属于结构/网表问题，而不是把 DFT Signal 名称换一下就能解决。修复前要保留原网表证据，并用 LEC 证明功能仍等价（任务二适用）。

### 2.5 锁存器、RAM、常量时序单元与 LS/TE

- 非扫描锁存器可能无法通过链访问，必须初始化、旁路或采用工具支持的替代结构；
- RAM 的内部存储通常不直接纳入普通 Scan Chain，需要专用 MBIST 或边界策略；
- 常量连接的时序单元可能永远装入同一值，导致可控性或覆盖率问题；
- 带 `LS/TE` 等特殊引脚的单元，必须依据 Liberty 的功能和时序定义判断其真实角色，不能只凭缩写猜测。

教材把非扫描存储元件列为全扫描设计中的风险项，并建议初始化、旁路或使其透明；赛题的具体 DFTR 规则编号与判定条件仍以官方指南和工具手册为准。[英文 DFT 教材第 2.6 节](<../../学习材料/DFT补强/VLSI Test Principles and Architectures - Design for Testability.md>)

### 2.6 组合反馈、双向端口和三态总线

- **组合反馈**没有明确的存储边界，测试时状态可能不可控或振荡；优先重写 RTL，无法重写时才考虑测试模式下打断环路。
- **双向端口**在移位期间方向可能随 Scan Cell 内容变化，测试仪与内部驱动器会争用；通常要在移位时强制输入或输出方向。
- **三态总线**必须保证同一时刻只有一个驱动器开启；悬空总线还会产生不可预测值，降低故障覆盖率。[英文 DFT 教材第 2.6.1～2.6.5 节](<../../学习材料/DFT补强/VLSI Test Principles and Architectures - Design for Testability.md>)

## 3. Dofile 问题还是网表问题？

可以按这条决策路径处理：

```text
违规对象是否已被正确识别？
        ├─ 否 → 先修正 Liberty/网表解析或顶层设置
        └─ 是
           ↓
任务要求与 DFT 配置是否一致？
        ├─ 否 → 改 Dofile/约束，完整复跑
        └─ 是
           ↓
门级连接是否仍使时钟/控制不可控或存在结构冲突？
        ├─ 否 → 检查报告解析和验证环境
        └─ 是 → 任务二才考虑最小网表修复，并运行 EQY
```

任务一的 case 明确不允许修改网表；任务二只有在题目允许时才可以修改，而且必须比较修改前后的 Pre-scan 网表。[任务边界与评分规则](<../比赛入门文档/02-任务边界与评分规则.md>)

## 4. DFTR 规则卡片模板

为每个 DFTR1～DFTR17、DFTR-TIE、DFTR-L（编号以工具手册最终版本为准）建立同样的卡片：

| 字段 | 要写什么 |
| --- | --- |
| 规则语义 | 用一句话说清楚测试期间必须满足的条件 |
| 典型结构 | 画出违规单元、关键引脚和驱动锥 |
| 证据 | 日志、DRC 报告、网表片段、Liberty 定义和行号 |
| 允许修复 | 可改的 Dofile 参数或网表最小改动 |
| 禁止修复 | 不能通过 Ignore、屏蔽报告或改变题目范围绕过 |
| 复跑判据 | 哪些报告/波形/LEC 结果必须变成什么状态 |

规则编号和工具输出字段属于赛题专用事实，当前未获得广立微手册时只能记录“待确认”，不能把教材中的通用规则冒充工具判定。

## 5. 一个门级追踪示例

假设 DRC 报告指出 `FF17` 的时钟不可控：

1. 在网表中找到 `FF17.CK` 的直接驱动网；
2. 继续向前追踪，发现它由 `u_div.Q` 产生；
3. 找到 `u_div` 的时钟来自 `pll_clk`，没有测试旁路 MUX；
4. 根因是派生时钟未旁路，而不是 `scan_clock` 名称写错；
5. 若题目允许且库中有旁路结构，设计最小修改；否则在 Dofile 中选择工具支持的测试时钟策略；
6. 重新 DRC、建链、插链并检查 Scan Chain 报告，任务二再加 EQY。

这个过程的关键是“每一步都留下证据”，而不是凭报告的一行摘要猜测。
