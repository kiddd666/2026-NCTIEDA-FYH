# DFT 与规则负责人项目学习路线

**一句话定位：**你的主线不是先学习 Agent 框架，而是把“任务书要求如何转成 DFT 配置、如何从报告判断正确、出现 DRC 时如何定位根因”整理成 Agent 可检索、工具可执行、证据可复核的规则资产。

## 1. 你的职责边界与学习目标

团队已经把你定位为 **DFT Domain Expert + Rule Engineer**。你需要回答的是“这个 Scan Insertion 结果在 DFT 上是否正确，以及为什么”，并向两位队友交付规则和判据。

| 你主责     | 需要形成的能力                                                      | 对团队的接口                         |
| ---------- | ------------------------------------------------------------------- | ------------------------------------ |
| 任务书语义 | 把自然语言拆成 DFT Signal、Internal Scan、Lockup、Wrapper、输出要求 | `requirement_mapping` 与需求矩阵   |
| 配置映射   | 说明每项要求对应的工具对象、Dofile 位置和前置条件                   | 给 Agent 负责人提供领域约束          |
| DRC 根因   | 从 DRC/日志对象追到时钟、复位、门控、LS/TE、Latch/RAM 等网表结构    | 与工具负责人共写规则断言             |
| 结果验收   | 不以退出码为成功标准，核对报告、Post-scan、CTL、SCANDEF 和链结构    | `report_assertions` 与交叉复核清单 |
| 修复语义   | 区分改 Dofile、DFT 约束还是工作副本网表；网表修改须考虑 EQY LEC     | 与 Agent 负责人定义路由边界          |

任务一的硬边界是 **禁止修改输入 Pre-scan 网表**；任务二只有必要时才改工作副本，且最终采用网表必须通过 Yosys EQY。任务一正确性 60 分、任务二问题识别与修复各 30 分，均直接依赖上述能力。

## 3. 推荐阅读与产出顺序

下图表示从共同规则到可执行规则资产的唯一主线；每一阶段都要有小实验和交叉复核，不能只做摘抄。

```mermaid
flowchart LR
    A[赛题边界与评分] --> B[数字设计与门级网表]
    B --> C[Scan Cell与Internal Scan]
    C --> D[多时钟/边沿/Lockup]
    D --> E[Wrapper、CTL、SCANDEF]
    E --> F[DFTR/DRC根因]
    F --> G[Dofile与报告验收]
    G --> H[EQY与任务二闭环]
    H --> I[规则卡片与自动断言]
```

### 阶段一：规则边界和术语

- 阅读 00、01、02、04、03、赛题指南第 4/5/8 章。
- 产出“任务一/任务二对照表”和术语表，至少区分 Dofile 执行错误、DRC 问题、DFT 配置不符三类问题。
- 关口：能说清任务一网表只读、任务二网表修改与 LEC 条件、`final_run`/`decision_log`/输出目录关系。

### 阶段二：数字设计与门级网表观察

- 读数字设计教材第 2～4 章和英文 DFT 教材第 1.3 节。
- 用一个小型结构化 Verilog（或已有 Public case）标注顶层端口、DFF/DLATCH、时钟、复位、MUX、门控时钟和控制锥。
- 产出 `design_summary` 草案：`top_module`、`clocks`、`resets`、`sequential_cells`、`clock_domains`、`gated_clocks`、`async_controls`。
- 关口：另一位成员复核后，你能从实例名追到单元引脚和控制来源。

### 阶段三：Internal Scan、时钟域与 Lockup

- 读英文 DFT 教材第 2.2～2.7 节；用中文教材第 5～6 章补概念。
- 重点掌握 Scan Cell replacement、Full/Partial Scan、链数/链长、scan ordering、时钟域、正负边沿、shift/capture 和 Lockup Latch/FF。
- 产出：三类 Scan Cell 对照表、双时钟/混合边沿手工插链案例、`internal_scan_rules` 与 `lockup_rules` 初稿。
- 关口：面对两个时钟域和正负沿触发器，能给出链分组、Lockup 位置、风险和待核对报告。

### 阶段四：Wrapper、DRC 和需求矩阵

- 读英文教材第 10.4.2～10.4.5 节、中文教材第 12.2～12.4 节；结合赛题指南整理 Wrapper 语义。
- 把任务书逐条拆成“原始要求 → DFT 含义 → 设计对象 → Dofile 配置 → 报告字段 → 验收断言”。至少覆盖 DFT Signal、Internal Scan/Lockup、Wrapper、输出文件。
- 按 DFTR1～DFTR17、DFTR-TIE、DFTR-L 建立规则卡片：现象、检查对象、根因假设、允许修复、禁止绕过、复跑判据、证据定位。
- 产出 `requirement_matrix.md/json`、`drc_rules/` 模板、Wrapper 配置核验表。
- 关口：每条关键要求均有对应配置对象和报告，不以工具退出码代替成功；未确认的工具事实明确标注“待手册校准”。

### 阶段五：Dofile、报告验收与 EQY 闭环

- 工具手册/Public case 到位后，按“加载 → 配置 → DRC → 链预生成 → 插入 → 报告 → 写出”顺序反向阅读正确 Dofile；不要逐行模仿。
- 建立报告断言：`scan_signal.rpt`、`scan_configuration.rpt`、`scan_chain.rpt`、`scan_chain_cell.rpt`、Wrapper 报告、Post-scan、CTL、SCANDEF。
- 用 EQY 做“等价成功、环境/模型配置失败、真实不等价”三个最小案例。
- 复盘至少 6 个任务二问题，按“现象 → 对象 → 根因 → 最小修复 → 复跑证据”记录，并明确何时改 Dofile、约束或网表。
- 关口：完成一次无人提示的模拟交付包，需求覆盖、报告断言、问题闭环、LEC（如需）和 `final_run` 一致。

## 4. 你的交付物路线（与 TODO 对齐）

建议按以下顺序把学习笔记变成团队可用资产；先完成 P0，再做 P1。

| 优先级 | 交付物                                                      | 验收标准                               | 协作对象                 |
| ------ | ----------------------------------------------------------- | -------------------------------------- | ------------------------ |
| P0     | `00_scan_overview`/术语表                                 | 能解释两任务与 Scan 闭环               | 全队                     |
| P0     | `requirement_matrix.md/json`                              | 每条要求均指向配置和报告               | Agent 与系统             |
| P0     | `signal_rules`、`internal_scan_rules`、`lockup_rules` | 有适用条件、反例和报告证据             | Agent 与系统、工具与质量 |
| P0     | `drc_rules/`                                              | DFTR 卡片包含根因、允许/禁止修复和验证 | 工具与质量               |
| P1     | `design_summary`/网表特征字段                             | 可从实例和引脚追踪时钟/复位/门控       | 工具与质量               |
| P1     | `manual_taxonomy`                                         | 按对象、命令、DRC 编号、报告字段检索   | Agent 与系统             |
| P1     | `report_assertions`                                       | 能发现“工具成功但配置不符”           | 工具与质量               |

## 5. 暂缓事项与学习纪律

- 暂缓复杂 Multi-Agent 框架、LLM4EDA 论文泛读、完整 JTAG/边界扫描和教材中与当前 case 无关的存储器章节。
- 不把通用教材规则直接写成广立微 DFTR 定义；正式规则只引用赛题指南、工具手册和真实报告。
- 不先写网表修改器再补 LEC；先把 EQY 最小案例跑通，再开放任务二网表修复能力。
- 每次学习遵循“阅读 → 小实验 → 结构化产物 → 另一位成员复核”，并把新缺口登记到[缺口报告](../../../学习材料/DFT与设计知识学习缺口报告.md)。

## 6. 自测清单

- [ ] 能从 `task_spec.md` 提取 DFT Signal、链数/长度、时钟域/边沿、Lockup、Wrapper 和输出要求。
- [ ] 能从门级网表与 Liberty 识别时序单元、控制路径、门控时钟和潜在 DRC 结构。
- [ ] 能解释每条配置的 Dofile 对象、前置条件和预期报告。
- [ ] 能区分 Dofile 执行问题、DFT 配置问题和网表根因，并给出最小修复。
- [ ] 能用报告核对链数、链长、时钟域、Wrapper 范围及输出完整性。
- [ ] 任务二修改网表时，能解释 EQY 结果并把 LEC 作为最终采用条件。
- [ ] 能让 `decision_log` 的 `requirement_mapping`、`issue_resolutions`、`config_ref`、`artifact_ref` 与真实文件闭合。
