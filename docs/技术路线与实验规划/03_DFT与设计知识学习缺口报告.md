# DFT 与设计知识学习缺口报告

## 1. 核心结论

现有 `学习材料/DFT补强/` 能够较完整地支撑数字设计、测试原理、Internal Scan、通用 Scan DRC、Lockup、IEEE 1500 Wrapper 和 CTL 的理论学习，但**不能单独覆盖本赛题所需的全部 DFT 与设计能力**。

缺口主要集中在“从教材原理到比赛工具闭环”的转换层：

1. 广立微 Scan Insertion 的 Dofile 命令与执行状态；
2. DFTR1～DFTR17、DFTR-TIE、DFTR-L 的精确定义与工具证据；
3. 真实门级 Verilog 与 Liberty 的联合分析和最小修复；
4. Yosys EQY 逻辑等价检查；
5. Wrapper 的工具级配置、SCANDEF 和结果报告验收。

因此，三本教材适合作为理论主干，但广立微工具手册、Public case、实际 Liberty、工具报告和 EQY 实操资料必须作为独立补充来源。

### 2.2 覆盖等级

| 等级 | 含义 |
| --- | --- |
| 充分覆盖 | 本地教材能够支持理解、推导和基础练习 |
| 部分覆盖 | 有原理，但缺少比赛工具语义或可执行验证 |

## 4. P0 缺口：不补齐就无法稳定完成比赛

### 4.1 GAP-01：广立微 Dofile 与工具状态机

**覆盖等级：未覆盖。**

现有三本教材没有广立微 Scan Insertion 的命令名称、参数约束、对象语义和执行阶段。赛题却要求 Agent 自主生成或修复 Dofile，并处理命令、路径、对象、加载顺序和前置步骤错误。

需要补齐：

- 网表、Liberty 和顶层设计的加载命令；
- DFT Signal、Internal Scan、Lockup、Wrapper 的配置命令；
- DRC、链预生成、插入、报告和输出命令；
- 命令之间的前置状态和不可逆状态；
- 对象选择为空、对象类型不匹配和参数冲突的日志表现；
- Dofile 静态检查与最小修改策略。

主要来源：

1. 广立微 Scan Insertion 用户手册；
2. Public case 的参考 Dofile；
3. 工具实际运行日志；
4. 正确 Dofile 与问题 Dofile 的语义 diff。

补齐产物：

- 命令知识库：命令、参数、对象、前置条件、产物、常见错误；
- Dofile 阶段状态机；
- 最小可运行 Dofile 模板，但不得硬编码某个 case 的设计对象。

完成判据：面对一个新 case，能够解释生成的每条命令为什么存在、依赖什么、应产生什么证据。

### 4.2 GAP-02：广立微 DFTR 规则语义

**覆盖等级：未覆盖；通用原理已覆盖。**

英文教材第 2.6 节可以解释时钟、复位、门控和组合环为什么影响 Scan，但不包含广立微 DFTR 规则的精确编号、判定逻辑和报告形式。

比赛明确涉及：

- DFTR1～DFTR7：DFF、DLATCH、RAM 的时钟、复位和置位可控性；
- DFTR8、DFTR9、DFTR17：时钟开启和数据捕获；
- DFTR10～DFTR12：时钟网络接入时序单元端口的错误；
- DFTR13～DFTR16：LS/TE 相关结构；
- DFTR-TIE0、DFTR-TIE1、DFTR-L1、DFTR-L2：常量时序单元和锁存器问题。

需要补齐：

- 每条规则的检查对象、触发条件和报告 locator；
- 一条根因产生多条违规时的聚合方法；
- 可通过 Dofile/DFT 约束解决的情形；
- 必须修改网表的情形；
- Ignore、降低等级、排除对象等禁止修复；
- 修复后应引用的正向证据。

主要来源：工具手册的 DRC 章节和 Public case 的 `preset_issues.json`。

补齐产物：DFTR 规则卡片库和最小违规网表集合。

完成判据：对每类预设问题，能够从报告对象回溯到网表结构，说明根因、最小修复和复跑判据。

### 4.3 GAP-03：门级 Verilog 与 Liberty 联合分析

**覆盖等级：部分覆盖。**

数字设计教材重点是 RTL 和通用 HDL；英文 DFT 教材会提到 Gate-level Netlist 与 Cell Library，但没有给出比赛所需的真实文件分析流程。

需要补齐：

- 结构化门级 Verilog 的实例、层次、转义标识符和命名/位置端口连接；
- DFF、DLATCH、RAM、ICG/门控时钟和测试单元识别；
- 时钟、复位、置位、使能从顶层端口到单元引脚的驱动锥；
- 常量、多驱动、组合反馈和时钟误接数据端等结构；
- Liberty 中时序单元、锁存器、时钟门控单元及引脚角色；
- 网表 cell type 与 Liberty cell 的一致性；
- 宏、黑盒和工具不支持单元的处理边界。

主要来源：实际 case 的 Pre-scan 网表、实际 Liberty、Liberty 参考资料和工具手册中的库要求。

补齐产物：结构化 `design_summary`、网表查询器测试集和典型结构样例库。

完成判据：能够从某条 DFTR 报告的实例名出发，定位对应单元、引脚、驱动路径和控制来源。

### 4.4 GAP-04：Yosys EQY 逻辑等价检查

**覆盖等级：未覆盖。**

任务二修改 Pre-scan 网表时，最终采用的网表必须通过 Yosys EQY。现有教材没有 EQY 配置、运行与报告诊断内容，教材中的“等价”概念不能替代正式 LEC。

需要补齐：

- Gold 与 Gate 两侧的文件和顶层设置；
- Liberty/Verilog 单元模型和黑盒处理；
- 层次、参数、未解析单元和名称变化；
- 成功、未证明、配置失败和真实不等价的区别；
- Counterexample 或失败分区的定位；
- LEC 与 Scan 复跑的先后关系及预算成本。

主要来源：Yosys EQY 官方文档、官方评测脚本和自建最小案例。

补齐产物：至少包含“等价成功、配置错误、真实不等价”三类结果的练习集，以及确定性的 EQY 执行器。

完成判据：不只报告 EQY 退出状态，还能解释失败是环境/模型问题还是功能改变。

## 5. P1 缺口：影响配置正确性和结果验收

### 5.1 GAP-05：Wrapper 的工具级配置

**覆盖等级：部分覆盖。**

两本 DFT 教材能够解释 IEEE 1500 Wrapper、Wrapper Cell、WIR、WBR 和 CTL，但下列比赛配置仍依赖广立微手册和 Public case：

- Shared/Dedicated Wrapper Cell 的准确语义；
- Wrapper 处理的端口范围；
- 输入、输出和双向端口的配置方式；
- Internal Clock、Clock-Gating 和 Wrapper 控制信号；
- Wrapper Chain 的数量、长度和连接；
- Wrapper Configuration/Implementation 报告的字段与成功判据。

补齐产物：Wrapper 配置矩阵和至少一个 Internal Scan + Wrapper Scan 联合案例。

完成判据：能从任务书的 Wrapper 要求推导 Dofile 配置，并从两类 Wrapper 报告证明其生效。

### 5.2 GAP-06：SCANDEF 与比赛交付物语义

**覆盖等级：部分或未覆盖。**

英文和中文 DFT 教材包含 CTL，但现有三本材料未形成可用于本赛题的 SCANDEF 学习内容。比赛还要求根据任务说明输出 Post-scan、CTL、SCANDEF 和多类报告。

需要补齐：

- CTL 与当前工具输出的对应关系；
- SCANDEF 的用途、链定义和基本一致性；
- 哪些交付物是无条件要求，哪些由任务说明决定；
- Post-scan、Scan Chain Report 与 SCANDEF 的交叉核验；
- 输出文件缺失、为空或与 `final_run` 不一致的判定。

主要来源：工具手册、正式输出契约和 Public case 的真实交付物。

补齐产物：交付物清单、基本解析器和跨文件一致性检查表。

完成判据：能指出每个输出文件证明什么，不能证明什么，并识别文件间的矛盾。

### 5.3 GAP-07：工具报告驱动的配置验收

**覆盖等级：部分覆盖。**

英文教材包含 Scan Verification 原理，但比赛要求以具体报告证明链数、链长、时钟域、边沿、Lockup、Wrapper 范围和端口纳入情况。工具成功退出不能证明这些要求已经满足。

需要补齐的报告包括：

- `scan_signal.rpt`；
- `scan_element.rpt`；
- `scan_configuration.rpt`；
- `scan_chain.rpt`；
- `scan_chain_cell.rpt`；
- `wrapper_configuration.rpt`；
- `wrapper_implementation.rpt`；
- DRC、日志和 Post-scan 网表。

补齐产物：每类报告的解析 Schema、任务要求核验器和“证据不足”状态。

完成判据：对任务书中的每条原子要求，都能找到正向报告证据；无法证明时明确输出“证据不足”，而不是猜测成功。

## 6. P2 缺口：可在主链跑通后深化

### 6.1 GAP-08：测试单元、宏和特殊结构的案例库

**覆盖等级：部分覆盖。**

教材分别讲解 DFF、Latch、RAM、门控时钟和 Wrapper，但缺少与实际 Liberty、实际网表命名和工具识别相匹配的案例库。

建议在 Public case 到位后逐步积累：

- Scan/Non-scan DFF；
- 正沿/负沿 DFF；
- 同步/异步置位复位；
- DLATCH；
- Integrated Clock Gating；
- RAM/Memory Macro；
- LS/TE 结构；
- 常量时序单元；
- Wrapper Cell。

补齐产物：每种结构一份最小网表、Liberty 片段、预期工具识别结果和典型 DRC。

### 6.2 GAP-09：从原理术语到工具术语的对照

**覆盖等级：待确认。**

教材、赛题说明和广立微工具可能对同一概念使用不同名称。例如教材中的 Scan Stitching、Clock Grouping、Wrapper Cell 与工具命令/报告字段未必同名。

补齐产物：三列表述对照表——“教材术语—赛题要求—工具命令/报告字段”。

完成判据：检索器能从任务书用词稳定找到对应手册章节，不依赖单一英文关键词。

## 7. 不属于 DFT 教材、但属于比赛的能力缺口

以下内容不应误记为 DFT 理论缺失，但仍是比赛正式能力的一部分：

- 自然语言任务结构化；
- PDF 工具手册检索与带页码引用；
- Agent 状态机、预算和停止策略；
- 工具调用、日志留存和不可变运行目录；
- `decision_log.json` 的引用闭合；
- diff、`final_run` 与 `final_results` 一致性；
- 无人值守运行和受保护文件权限控制。

这些内容应在 Agent 与系统路线中另行实现。DFT 学习产物需要为系统提供结构化规则和验收判据，但不负责代替系统工程。

## 8. 缺口补齐顺序

下图说明补齐顺序。工具手册和 Public case 到位后，必须先完成事实校准，再进入大规模自动化。

```mermaid
flowchart LR
    A["立即开始<br/>门级 Verilog、通用 Scan、EQY 最小案例"] --> B["材料到位<br/>工具手册、Public case、Liberty"]
    B --> C["事实校准<br/>Dofile 命令、DFTR、Wrapper、报告"]
    C --> D["结构化沉淀<br/>规则卡、Schema、样例库"]
    D --> E["自动化实现<br/>分析器、生成器、诊断器"]
    E --> F["回归验证<br/>Public case 与故障注入"]
```

推荐优先级：

1. **立即补齐 GAP-03、GAP-04 的基础部分**：不依赖广立微工具即可练习；
2. **资料发放后优先补齐 GAP-01、GAP-02**：直接影响任务一和任务二核心正确性；
3. **随后补齐 GAP-05～GAP-07**：建立配置和报告的正向验收；
4. **主链稳定后积累 GAP-08、GAP-09**：增强 Hidden case 泛化能力。

## 10. 风险与控制措施

| 风险 | 后果 | 控制措施 |
| --- | --- | --- |
| 用教材通用规则代替广立微 DFTR 定义 | 根因和修复判断错误 | 工具规则只引用正式手册或真实报告 |
| 从正确 Dofile 逐行模仿而不理解状态 | Hidden case 对象或要求变化时失效 | 每条命令记录语义、前置条件和证据 |
| 只解析日志中的 `Error` | 漏掉成功退出但配置不符 | 强制执行需求—报告核验矩阵 |
| 先写复杂网表修改器，后补 LEC | 产生无法证明等价的修复 | 先练通 EQY，再开放网表修改能力 |
| 把未发放资料的内容凭经验补全 | 形成错误知识库并污染检索 | 明确标记待确认，不进入正式规则库 |
| 三人各学一块且缺少共同底座 | 形成单点依赖，难以交叉复核 | 核心课程共同必修，关键产物交叉复核 |

## 11. 总结

当前 `DFT补强` 的优势是理论覆盖宽、Internal Scan 主线清晰，并且英文教材与赛题推荐文献一致。真正的短板不在“再找一本更厚的 DFT 教材”，而在于补齐以下工程闭环：

```text
工具手册语义
→ 真实网表与 Liberty
→ Dofile 和 DFTR
→ 工具日志与结构报告
→ 最小修复
→ EQY 与 Scan 复跑
→ 正向证据验收
```

缺口的后续状态、材料到位情况和完成证据应持续更新在本报告中；具体学习顺序与阶段验收见[《DFT 与设计知识学习地图及学习大纲》](DFT与设计知识学习地图及学习大纲.md)。
